# Mission 02 — 나만의 퀴즈 게임 (Python 콘솔)

터미널에서 동작하는 **파이썬 문법 4지선다 퀴즈 게임**입니다.

- 파이썬 기본 문법으로 입력 → 처리 → 출력 흐름을 만들고,
- 역할이 다른 일을 **클래스 3개**(`Quiz` / `Storage` / `QuizGame`)로 나누고,
- **`state.json`** 파일에 저장해서 프로그램을 껐다 켜도 퀴즈와 최고 점수가 남게 하고,
- 기능 하나를 완성할 때마다 커밋해서 **개발 과정이 Git 이력에 남도록** 만들었습니다.

## 2) 퀴즈 주제와 선정 이유

**주제: 파이썬 문법**

3년 전에 파이썬을 공부했지만 오래 쓰지 않아 기억이 흐려진 상태였습니다.
그래서 이번 미션을 **"만들면서 동시에 복습하는" 도구**로 쓰기로 했습니다.

주제를 파이썬 문법으로 잡으니 세 가지가 한 번에 해결됐습니다.

1. **문제를 만들려면 먼저 내가 알아야 한다** — 문제·선택지·정답을 직접 쓰는 과정 자체가 복습이었습니다.
   특히 헷갈렸던 `self`, `__init__`, `open()`의 모드 문자는 문제로 만들면서 확실히 정리됐습니다.
2. **기본 10문제를 이번 미션의 학습 목표에 맞춰 배치**했습니다.
   자료형(2문제) / 조건문 / 반복문 / 함수(2문제) / 클래스(2문제) / 파일 입출력 / 예외 처리 —
   즉 **이 게임을 한 판 풀면 이번 과제의 핵심 문법을 한 바퀴 훑게** 됩니다.
3. **만드는 코드와 문제의 내용이 같아서** 서로 검증이 됩니다.
   예를 들어 "`try/except`는 무엇인가"를 문제로 내면서, 실제로 `Storage.load()`에서
   `try/except`로 손상된 파일을 복구하는 코드를 짰습니다. 문제의 답이 곧 내 코드에 있습니다.

> 기본 문제 전체는 [`default_quizzes.py`](default_quizzes.py)에 있습니다.

## 3) 실행 방법

```bash
git clone https://github.com/<계정>/codyssey-mission02-quiz-game.git
cd codyssey-mission02-quiz-game

python3.13 main.py
```

`python3`가 이미 3.10 이상이라면 `python3 main.py`로도 실행됩니다.
버전은 아래로 확인합니다.

```bash
$ python3.13 --version
Python 3.13.14
```

> **3.10 이상이 필요한 이유**: 메뉴 분기에 파이썬 3.10에서 추가된 `match/case` 문법을 사용합니다.
> 3.9 이하에서 실행하면 `SyntaxError`가 납니다. ([10) 트러블슈팅 사례 1](#10-트러블슈팅) 참고)

설치가 필요하면 (macOS + Homebrew 기준):

```bash
brew install python@3.13
```

## 4) 기능 목록

| 번호 | 기능 | 하는 일 | 담당 메서드 |

| 1 | 퀴즈 풀기 | 등록된 문제를 순서대로 출제 → 채점 → 100점 만점 결과 표시, 최고 점수 갱신 | `QuizGame.play_quiz()` |

## 5) 파일 구조

```
E1-2/
├── main.py              # 진입점 — 게임 실행 + Ctrl+C/EOF 안전 종료 처리
├── quiz.py              # Quiz 클래스 — 문제 1개를 표현
├── quiz_game.py         # QuizGame 클래스 — 메뉴/게임 진행 전체 관리
├── storage.py           # Storage 클래스 — state.json 읽기/쓰기
├── input_utils.py       # 입력 검증 공통 함수 (ask_number / ask_text)
├── default_quizzes.py   # 기본 파이썬 문법 퀴즈 10문제
├── state.json           # (실행하면 생성) 퀴즈 목록 + 최고 점수 — .gitignore 처리
├── .gitignore
├── README.md            # 이 문서
└── docs/
    └── screenshots/     # 실행 화면 / 개발 환경 / git log 캡처
```

**구성 기준**: ① **파일 하나 = 역할 하나**로 나눴습니다. "문제를 표현하는 일"(`quiz.py`),
"파일을 다루는 일"(`storage.py`), "게임을 진행하는 일"(`quiz_game.py`)은 성격이 다른 작업이라
한 파일에 섞으면 나중에 한 곳을 고칠 때 다른 곳이 함께 흔들립니다.
② 입력 검사는 메뉴·정답·퀴즈 추가 등 **여러 곳에서 똑같이 반복**되므로 `input_utils.py`로 빼서
한 번만 고치면 전부 적용되게 했습니다.
③ 기본 데이터(`default_quizzes.py`)는 코드가 아니라 **내용물**이므로 로직과 분리했습니다.

### 클래스 설계

| 클래스 | 파일 | 책임 | 주요 속성 | 주요 메서드 |
|---|---|---|---|---|
| `Quiz` | `quiz.py` | 문제 **1개**를 표현하고 채점 | `question`, `choices`, `answer` | `show()`, `is_correct()`, `to_dict()`, `from_dict()` |
| `Storage` | `storage.py` | `state.json` 읽기/쓰기와 복구 | `path` | `load()`, `save()` |
| `QuizGame` | `quiz_game.py` | 메뉴 진행과 전체 흐름 관리 | `quizzes`, `best_score`, `storage` | `run()`, `play_quiz()`, `add_quiz()`, `show_quiz_list()`, `show_score()` |

`QuizGame`은 "JSON으로 저장한다"는 사실을 몰라도 되고(`self.storage.save(...)`만 호출),
`Storage`는 게임 규칙을 몰라도 됩니다. 나중에 저장 방식을 파일에서 DB로 바꿔도
`storage.py`만 고치면 됩니다.

## 6) 데이터 파일 설명 — `state.json`

| 항목 | 내용 |
|---|---|
| 경로 | 프로젝트 루트 `./state.json` (`storage.py` 위치 기준 절대 경로로 계산) |
| 인코딩 | UTF-8 (`ensure_ascii=False`로 한글을 그대로 저장) |
| 역할 | 등록된 퀴즈 전체와 최고 점수를 보관 → 프로그램을 껐다 켜도 유지 |
| 생성 시점 | 첫 실행 후 저장이 일어날 때 자동 생성 |
| Git 추적 | **제외**(`.gitignore`) — 실행하면 생기는 데이터라서 |

### 스키마

```json
{
  "quizzes": [
    {
      "question": "참(True)과 거짓(False) 두 가지 값만 가질 수 있는 자료형은?",
      "choices": ["int", "str", "bool", "list"],
      "answer": 3
    }
  ],
  "best_score": 80
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `quizzes` | list | 퀴즈 객체들의 목록 |
| `quizzes[].question` | str | 문제 내용 (빈 문자열 불가) |
| `quizzes[].choices` | list[str] | 선택지 **정확히 4개** |
| `quizzes[].answer` | int | 정답 번호 **1~4** (0부터 세지 않음 — 화면 번호와 일치) |
| `best_score` | int | 최고 점수 (100점 만점 환산) |

### state.json을 커밋하지 않는 이유

`state.json`은 **소스 코드가 아니라 실행 결과로 쌓이는 데이터**입니다.
커밋하면 게임을 한 판 풀 때마다 점수가 바뀌어 매번 변경 사항으로 잡히고,
여러 사람이 각자 다른 점수로 커밋하면 충돌만 납니다.

대신 **파일이 없어도 프로그램이 정상 동작하도록** 만들었습니다.
`clone` 직후 처음 실행하면 `default_quizzes.py`의 기본 10문제로 시작합니다.

```bash
$ python3.13 main.py
📂 저장된 데이터가 없어 기본 퀴즈로 시작합니다. (state.json 없음)
```

## 7) 입력 / 예외 처리

숫자를 받는 모든 곳(메뉴 선택, 정답 입력, 정답 번호 입력)은 `input_utils.ask_number()` 하나를 씁니다.

| 상황 | 입력 예 | 프로그램 동작 | 확인 |
|---|---|---|---|
| 앞뒤 공백 | `"  1  "` | `.strip()` 후 `1`로 정상 처리 | ✅ |
| 숫자가 아님 | `abc` | `⚠️ 숫자만 입력할 수 있습니다.` → 재입력 | ✅ |
| 범위 밖 | `9`, `0` | `⚠️ 1-5 범위를 벗어났습니다.` → 재입력 | ✅ |
| 빈 입력 | (그냥 Enter) | `⚠️ 입력이 비어 있습니다.` → 재입력 | ✅ |
| 빈 문제/선택지 | (그냥 Enter) | `ask_text`가 막고 재입력 | ✅ |
| Ctrl+C | `KeyboardInterrupt` | 안내 후 **저장하고** 정상 종료(exit 0) | ✅ |
| 입력 스트림 종료 | `EOFError` | 위와 동일 | ✅ |
| 데이터 파일 없음 | — | 기본 퀴즈 10문제로 시작 | ✅ |
| 데이터 파일 손상 | `{ 깨진내용` | 안내 후 기본 퀴즈로 복구 | ✅ |
| 퀴즈 0개인데 풀기 시도 | — | 안내 후 메뉴로 복귀 | ✅ |

**실제 동작 확인**

```bash
$ python3.13 main.py
선택: abc
⚠️  숫자만 입력할 수 있습니다. 1-5 사이의 숫자를 입력하세요.
선택: 9
⚠️  1-5 범위를 벗어났습니다. 다시 입력하세요.
선택:
⚠️  입력이 비어 있습니다. 1-5 사이의 숫자를 입력하세요.
선택:   5
👋 게임을 종료합니다. 수고하셨습니다!
```

```bash
# 파일을 일부러 깨뜨린 뒤 실행
$ echo '{ 깨진내용' > state.json
$ python3.13 main.py
⚠️  데이터 파일이 손상되어 기본 퀴즈로 복구합니다.
   (원인: Expecting property name enclosed in double quotes: line 1 column 3 (char 2))
```

`Storage.load()`가 잡는 예외는 **원인별로 나눠** 처리합니다.

| 예외 | 언제 발생 | 처리 |
|---|---|---|
| `json.JSONDecodeError` | 파일이 JSON 형식이 아님 | 기본 퀴즈로 복구 |
| `KeyError` | `quizzes` / `best_score` 키가 없음 | 기본 퀴즈로 복구 |
| `ValueError` | 선택지가 4개가 아니거나 정답이 1~4 밖 | 기본 퀴즈로 복구 |
| `TypeError` | 값의 타입이 예상과 다름 | 기본 퀴즈로 복구 |
| `OSError` | 파일 권한 문제 등으로 못 읽음/못 씀 | 안내 후 기본값 사용 |

```bash
$ git checkout main                     # main으로 복귀
$ git merge --no-ff feature/play-quiz   # 병합
$ git branch -d feature/play-quiz       # 병합 끝난 브랜치 정리
```

> `--no-ff`를 쓴 이유: 그냥 `merge`하면 커밋이 일렬로 붙어(fast-forward) **브랜치를 썼다는 흔적이 사라집니다.**
> `--no-ff`는 병합 커밋을 따로 만들어서 `git log --graph`에 갈래가 남습니다.

## 10) 트러블슈팅

### 사례 1 — `match choice:` 에서 `SyntaxError`

- **문제**: 메뉴 분기를 `match/case`로 바꾼 뒤 실행하니 프로그램이 시작조차 못 하고 문법 오류가 났습니다.
  ```
  File "/Users/tokomon/Documents/codyssey/E1-2/quiz_game.py", line 144
      match choice:
            ^
  SyntaxError: invalid syntax
  ```
- **원인 가설**: `SyntaxError`는 **코드를 실행하기도 전에** 파이썬이 문법을 읽다가 내는 오류입니다.
  즉 로직 문제가 아니라 "이 파이썬이 이 문법을 모른다"는 뜻. `match/case`는 파이썬 **3.10**에서 추가됐습니다.
- **확인**: macOS에 기본 설치된 파이썬 버전을 확인했더니 3.9였습니다.
  ```bash
  $ /usr/bin/python3 --version
  Python 3.9.6
  ```
- **해결**: Homebrew로 3.13을 설치하고 그것으로 실행했습니다. 과제 요구사항도 3.10 이상입니다.
  ```bash
  $ brew install python@3.13
  $ python3.13 --version
  Python 3.13.14
  $ python3.13 main.py      # 정상 실행
  ```
- **교훈**: "내 코드가 틀렸나?"부터 의심하기 전에 **오류의 종류**를 봐야 합니다.
  `SyntaxError`는 실행 전 단계의 오류라서 로직을 아무리 봐도 답이 안 나옵니다.
  그리고 `python3`가 항상 최신 버전을 가리키지는 않습니다.

### 사례 2 — Ctrl+C를 누르면 빨간 오류와 함께 죽고, 점수가 사라짐

- **문제**: 게임 도중 Ctrl+C를 누르면 아래처럼 `Traceback`이 뜨면서 종료됐고,
  직전에 추가한 퀴즈가 저장되지 않았습니다.
  ```
  Traceback (most recent call last):
    File ".../main.py", line 12, in <module>
      main()
    ...
  KeyboardInterrupt
  ```
- **원인 가설**: Ctrl+C는 파이썬 입장에서 `KeyboardInterrupt`라는 **예외**입니다.
  아무도 잡아 주지 않으면 그대로 위로 올라가서 프로그램을 죽이고,
  그 과정에서 `save()`를 부를 기회가 없습니다. 입력이 끊기는 `EOFError`도 마찬가지입니다.
- **확인**: `main()`을 `try/except`로 감싸 두 예외를 잡도록 수정한 뒤,
  실제로 SIGINT(Ctrl+C와 같은 신호)를 보내 종료 코드를 확인했습니다.
  ```
  === 종료 코드: 0 (0이면 정상 종료)
  ⚠️  입력이 중단되었습니다. 저장 후 종료합니다.
  👋 안전하게 종료되었습니다.
  === Traceback 포함 여부: False
  ```
- **해결**: `main.py`에서 `except (KeyboardInterrupt, EOFError)`로 받아
  안내 → 저장 → 정상 종료(코드 0) 순서로 처리했습니다.
- **교훈**: 예외 처리는 "오류를 숨기는 것"이 아니라 **"프로그램이 어떻게 끝날지 내가 정하는 것"**입니다.
  중요한 데이터가 있다면 끝나는 길목마다 저장이 걸려 있어야 합니다.

## 11) 학습 정리 (과제 목표 답변)

### 파이썬 기초

- **변수는 왜 쓰는가**: 값에 이름을 붙여 두면 나중에 그 이름으로 다시 꺼내 쓰고 바꿀 수 있습니다.
  `correct_count = 0`처럼 이름을 붙여 두었기 때문에 반복문을 돌면서 `correct_count += 1`로
  "지금까지 몇 개 맞혔는지"를 기억할 수 있습니다. 이름이 없으면 값은 계산되자마자 사라집니다.
- **`int` / `str` / `bool` / `list` / `dict`**: 이 프로그램에서 실제로 쓰인 자리로 설명하면 —

  | 타입 | 무엇 | 이 프로젝트에서 |
  |---|---|---|
  | `int` | 정수 | `answer`(정답 번호 1~4), `best_score`(점수) |
  | `str` | 문자열 | `question`(문제 내용), `input()`이 돌려주는 값 |
  | `bool` | 참/거짓 | `is_correct()`의 반환값 — `if`의 조건이 됨 |
  | `list` | 순서 있는 묶음 | `choices`(선택지 4개), `quizzes`(문제 목록) — **순서가 곧 번호**라서 리스트가 맞음 |
  | `dict` | 키-값 묶음 | `to_dict()`의 결과 — 순서가 아니라 **이름(`question`/`answer`)으로 찾기** 때문 |

  선택지는 "1번, 2번"처럼 순서가 의미를 가지므로 `list`, 저장 형식은 "어떤 값이 무엇인지"가
  중요하므로 `dict`를 썼습니다.
- **`if` / `elif` / `else`**: 조건에 따라 다른 일을 합니다.
  `ask_number()`에서 빈 입력 → 숫자 아님 → 범위 밖 순서로 검사하고, 각각 다른 안내를 냅니다.
  메뉴 분기는 `if/elif`와 같은 역할이지만 "값 하나를 여러 경우로 나눈다"는 의도가 드러나는
  `match/case`(3.10+)로 썼습니다.
- **`for`와 `while`의 차이**:
  - `for` = **반복 횟수가 정해져 있을 때**. 문제 10개를 순회하는 `for number, quiz in enumerate(...)`.
  - `while` = **언제 끝날지 모를 때, 조건이 참인 동안**. 메뉴 루프(`while True`)와
    올바른 입력이 들어올 때까지 다시 묻는 `ask_number()`의 루프.
  - 사용자가 몇 번 잘못 입력할지는 알 수 없으므로 입력 검증은 반드시 `while`이어야 합니다.
- **함수 / 매개변수 / 반환값**: `ask_number(prompt, min_value, max_value)`는
  **매개변수** 3개를 받아 검사한 뒤 올바른 정수를 **반환**합니다.
  같은 검사를 메뉴·정답·정답번호 세 곳에서 재사용하므로, 규칙을 바꾸려면 이 함수 하나만 고치면 됩니다.

### 클래스와 객체

- **클래스는 왜 쓰는가**: 클래스는 **"모양이 같은 것을 찍어내는 틀"**입니다.
  퀴즈는 전부 "문제 + 선택지 4개 + 정답"이라는 같은 모양이라, `Quiz` 틀을 한 번 만들어 두면
  문제가 10개든 100개든 같은 방식으로 다룰 수 있습니다.
  게다가 **데이터와 그 데이터를 다루는 기능이 한 덩어리로 묶입니다** —
  `quiz.is_correct(3)`처럼 "그 문제 자신에게 채점을 시키는" 식으로요.
- **`__init__`과 `self`**:
  - `__init__`은 **객체가 만들어지는 순간 자동으로 호출**되어 속성의 초기값을 채웁니다.
    `Quiz("문제", [...], 2)`라고 쓰면 파이썬이 알아서 `__init__`을 부릅니다.
  - `self`는 **지금 만들어지고 있는(또는 메서드를 호출한) 그 객체 자신**입니다.
    `self.question = question`이라고 써야 값이 객체 안에 남습니다.
    `self.` 없이 `question = question`이라고 쓰면 함수가 끝나는 순간 사라집니다.
    객체가 여러 개일 때 서로의 값이 섞이지 않는 이유도 각자 자기 `self`에 저장하기 때문입니다.
- **속성과 메서드**:
  - 속성(attribute) = 객체가 **가지고 있는 값** → `quiz.question`, `game.best_score`
  - 메서드(method) = 객체가 **할 수 있는 일** → `quiz.show()`, `game.play_quiz()`
  - `CHOICE_COUNT = 4`는 `__init__` 밖에 있는 **클래스 변수**입니다.
    객체마다 다를 이유가 없는 값(선택지는 항상 4개)이라 클래스가 하나만 들고 공유합니다.
- **`@classmethod`**: `Quiz.from_dict(data)`는 **객체를 만들기 전에** 호출해야 하므로
  `self`를 받을 수 없습니다. 그래서 클래스 자신(`cls`)을 받는 `@classmethod`로 만들고,
  내부에서 `cls(...)`로 새 `Quiz`를 만들어 돌려줍니다.

### 파일 입출력

- **파일을 열고 읽고 쓰는 과정**: `open(경로, 모드, encoding)`으로 열고 → 읽거나 쓰고 → 닫습니다.
  `with open(...) as f:` 를 쓰면 **블록을 벗어날 때 자동으로 닫혀서** 닫는 것을 잊을 수 없습니다.
  모드 `"r"`은 읽기, `"w"`는 쓰기(기존 내용 삭제)입니다.
  `encoding="utf-8"`을 지정해야 한글 문제가 깨지지 않습니다.
- **JSON이 무엇이고 왜 저장에 쓰는가**: JSON은 데이터를 표현하는 **텍스트 형식**입니다.
  파이썬의 `dict`/`list`와 구조가 거의 1:1로 대응해서 변환이 자연스럽고,
  사람이 열어서 눈으로 읽을 수 있으며, 파이썬이 아닌 다른 언어에서도 읽을 수 있습니다.
  그래서 `json.dump()`로 저장하고 `json.load()`로 그대로 복원할 수 있습니다.
  단, JSON은 `Quiz` 같은 **객체는 저장하지 못하므로** `to_dict()` / `from_dict()`로 번역해 줍니다.
- **`try/except`**: 오류가 날 수 있는 코드를 `try:`에 넣고, 실제로 나면 `except`에서 대응합니다.
  이 프로그램은 파일이 없거나 깨졌을 때 죽지 않고 **기본 퀴즈로 복구**합니다.
  `except:`로 모든 오류를 뭉뚱그리지 않고 `json.JSONDecodeError`, `KeyError`, `OSError`처럼
  **원인별로 나눠 잡아야** 어디가 문제인지 알 수 있습니다.

### Git 기초

- **Git이 왜 필요한가**: 코드의 변경 이력을 **되돌릴 수 있는 형태로** 남겨 줍니다.
  `파일_최종_진짜최종.py` 같은 복사본을 만들 필요가 없고,
  "언제 무엇을 왜 바꿨는지"가 커밋 메시지로 남으며, 실패해도 이전 커밋으로 돌아갈 수 있습니다.
  브랜치를 쓰면 여러 사람이 같은 코드를 동시에 고칠 수도 있습니다.
- **명령어별 역할**:

  | 명령어 | 하는 일 | 한 줄 비유 |
  |---|---|---|
  | `init` | 폴더를 Git 저장소로 만듦 | 기록장 펴기 |
  | `add` | 커밋에 포함할 변경을 고름 (스테이징) | 사진에 넣을 것 고르기 |
  | `commit` | 고른 변경을 이력으로 확정 | 사진 찍고 설명 달기 |
  | `push` | 로컬 커밋을 원격(GitHub)에 올림 | 앨범 업로드 |
  | `pull` | 원격의 변경을 로컬로 가져옴 | 앨범 내려받기 |
  | `checkout` | 브랜치/시점 이동 | 다른 작업 갈래로 갈아타기 |
  | `clone` | 원격 저장소 전체를 복제 | 앨범 통째로 새로 받기 |

- **Git과 GitHub의 차이**: Git은 **내 컴퓨터에서 이력을 관리하는 도구**,
  GitHub는 그 저장소를 **온라인에 두고 공유·협업하게 해 주는 서비스**입니다.
  Git은 인터넷 없이도 동작하고, GitHub는 Git 위에서 돌아갑니다.
- **브랜치와 병합**: `checkout -b`로 갈래를 만들어 거기서 작업하면 `main`은 그대로 유지됩니다.
  기능이 완성되면 `main`으로 돌아와 `merge`로 합칩니다.
  이번엔 `--no-ff`로 병합해 그래프에 갈래가 남게 했습니다.
